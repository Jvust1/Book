# Book 长期成长路线图

修订依据：2026-09-22 的项目证据与用户对“按项目成长扩大规划”的纠正。
这份路线图描述 Book 依次能够承担什么、覆盖多少课程、何时值得扩展。
成长由内容可信度、学习闭环、课程生产能力和真实需求驱动，不设到期自动升级。
下述能力、数量门槛和接口为提案；现有工作分支中的功能不能直接等同于整级验收。
全项目仍同时聚焦一个主项目和一个支撑项目；资源安排不改变本库的成长依赖。

## 2. 成长总览

| 成长级别 | 用户新获得的价值 | 能力与规模怎样扩大 | 升级驱动力 |
|---|---|---|---|
| G1 单门可信教材 | 能看完整原文并定位来源与疑点 | 从零散文本/扫描件到一册版本明确的教材包 | 解决来源、完整性和数学正确性问题 |
| G2 完整课程学习 | 能围绕同一课程持续预习、学习、复习、刷题 | 从教材阅读到课程行为与记录闭环 | 实际学习任务需要连续性 |
| G3 可重复的多课程生产 | 新教材可沿同一流程进入 App | 从一门特制课程到至少两门可重复导入课程 | 第二门教材暴露共性与差异 |
| G4 个人学习系统 | 多门课程、记录和复习相互关联且可恢复 | 从独立课程包到个人课程组合与可解释反馈 | 用户确实同时管理多课程 |
| G5 有条件的学习协作 | 允许其它工具提供帮助而不夺走内容权威 | 从本应用内部到少量可撤销的语义接口 | 真实跨库任务无法更简单完成 |

可以长期停留在任何一级；高一级不是低一级“完成后必须做”的附加负担。
每本教材分别记录所处状态：一册达到 G1，不使其它未完成教材自动获得同一状态。
App 能力与教材成熟度分列，不能用 App 测试通过替代内容验收。

## 3. 不随规模改变的原则

- App 通用，课程与教材为独立、版本化的数据；一门课程当前启用一本主教材。
- 教材原文、编辑校注、AI 推导、学习记录、录音和私人会议数据分别存储、标识和授权。
- 四种学习入口自由选择，不把停留时长、点击次数或 Session 数量当作掌握程度。
- 来源页、印刷页与物理页不是一回事；未取得原件时不猜页码或重造原图。
- MathJax 语法成功、结构检查和数学正确性分别验收。
- H3b、B4b、B5、StudyRecord 版本迁移及新检索架构仍需原有独立门禁。
- 本路线图不授权合并 PR、改写 main、覆盖 Golden 内容或改变冻结结论。
- 模型提出的解释必须能被标为待核；模型不可用时基础阅读与记录继续可用。

## 4. G1：从零散材料长成单门可信教材

### 进入条件

选择一册具有明确书名、作者、版本和授权来源的教材，明确本次来源能读取到哪里。
核对当前源码、数据包、开放 QC 与原始文件身份；已有可复用成果直接承接。
经济教材按各自阻碍处理：《货币金融学》先核验现有初稿，《当代中国经济》先恢复身份与正文。

### 扩展内容与用户价值

用户从“能搜到一段文字”升级为“能读完整段落、公式、原图，并知道它来自哪里”。
建立来源清单、连续页覆盖、正文层次、题目/图表索引与逐项 QC 队列。
保留原文顺序与跨页连接，不能用摘要替代证明、推导过程或表格内容。
校正记录同时保存原识别结果、修改后文本、修改依据和核验状态。
AI 补充推导独立保存，不回写成教材原文，也不冒充书后标准答案。
对复杂公式、低清图和表格保留原始图像引用与待核标记。
规模只扩大到一册教材的来源完整性，不同时承诺所有教材完工。

### 验收与升级门槛

- 正式教材包的正文、题目、图表和来源引用闭合，缺失项为零。
- 存在缺页或缺图的版本只能作隔离初稿/局部试用，不计入整书完成。
- 每个包记录 source commit、大小、SHA-256、Drive ID 与实际验证范围。
- 结构审查、定点 PDF 疑点、全页视觉核验、数学独立审查分别统计。
- 高风险未解决内容不进入正式学习包，所有已识别疑点可定位到来源与下一动作。
- 针对原文/校注/推导至少核验 20 个身份与回链样例，不发生层级混淆。

### 止步或收缩条件

来源受阻、教材身份不明或数学错误未定位时，停留在初稿层，继续已有内容检查。
《当代中国经济》正文仍缺时不得推测补齐；不能把内部包名直接判成用户文件错误。
《货币金融学》501 项 QC 先按风险分类，发现新问题允许总数增加，不以数字下降伪装质量。
数学课程 r6 与两种不同《泛函分析》来源分别验收，不把一个教材的成果转记给另一个。

## 5. G2：从可信教材长成完整课程学习

### 进入条件

至少一册教材具备 G1 的正式验收证据；当前 App 候选有准确源码与可重建工程。
Android Studio 能恢复指定源码；课程包与学习记录身份已明确，记录不依赖临时聊天。

### 扩展内容与用户价值

用户能够围绕同一小节切换四模式，并在重启、离线与换设备后继续学习。
预习呈现先备知识和待思考问题；学习呈现完整正文与原图。
复习提供来源锚点与回忆提示；刷题区分原题、提示、参考推导和已核答案。
补齐最近位置、模式独立状态、本地持久化记录和离线课程安装。
正文支持 12–72px 自由字号及小数；书宋真实加载与替代字体分别显示验收结果。
长公式可滚动或合理换行，不能为了窄屏截掉数学内容。
规模从“一册内容”扩为“一门课程的反复使用”，不急于增加课程数量。

### 验收与升级门槛

- 至少 20 次真实小节学习任务覆盖四模式、退出重进与断网恢复，学习记录丢失为零。
- Android 真机完成 30 次启动、退出、重启及断网往返，关键状态保持一致。
- 390px 级窄屏及常用大字号不出现正文裁切，公式可被完整查看。
- Android/Windows 抽取至少 20 个来源锚点，题目身份与内容一致。
- 同一记录包导入两次，第二次不产生无意义 revision；UTC、冲突和损坏输入均有结果。
- 记录包中断导入后可恢复，旧笔记与教材版本不被静默覆盖。

### 止步或收缩条件

出现记录丢失、同步冲突无法解释或阅读阻断时，暂停新功能和新课程扩张。
缺原生构建或设备证据时保持候选，网页测试不替代真机验收。
字体授权未明确时使用清楚标识的替代，不分发无权使用的字体文件。
若四模式只有入口没有不同学习任务价值，先完善一门课程的实际使用。

## 6. G3：从单门课程长成可重复的多课程生产

### 进入条件

一门课程已实际形成 G2 闭环，且用户有第二门来源明确、确实要学习的课程。
先比较第二门的排版、章节、公式、习题与原图差异，再决定需增强哪段导入流程。

### 扩展内容与用户价值

形成“来源登记—连续页覆盖—原图—正文结构—QC—独立验收—课程注册”的可重复流程。
每条记录保留教材版本、章节、来源区间、结构类型和质量状态。
第二门开始复用工具与合同，新课程提供数据包和声明，不加课程专属 App 条件分支。
将图表、定义、定理、证明、例题和题目建立统一最小模型，保留教材自己的教学顺序。
两门经济教材均沿该流程完成结构化；原件依赖按各书实际状态解除，不混作一个完成项。
新增课程的排队依据是用户需求与来源可用性，不以课数增长为唯一目标。

### 验收与升级门槛

- 至少两门不同教材通过同一导入工具和质量门，课程差异不要求修改 App 业务代码。
- 同输入、工具版本和配置重复生成，业务内容哈希相同；时间戳独立存储。
- 新课程异常不会污染已验收课程；失败包可隔离并重新处理。
- 所有高风险开放项有责任任务、来源锚点和下一核验动作。
- 新数据包接入后能恢复指定旧版本，校注和题目身份不串书。
- 每次更换生成工具或包格式都做一次代表性恢复与回归，身份清单完整。

### 止步或收缩条件

每加一本书都需定制 App 时，先修复合同与适配边界，不继续批量导入。
QC 增长超过审校能力时减少并行书目，不以低质量批量文本冒充生产线。
保持现有 Python Runtime、SQLite 与前端合同；新数据库或服务须由实测瓶颈触发。
来源授权和可读性不足的课程留在待处理清单，不拖累已验收课程。

## 7. G4：从多课程集合长成个人学习系统

### 进入条件

多课程导入已可重复，用户确实存在跨课程查阅、长期记录或复习组织需求。
数据版本和记录恢复可靠；任何版本迁移先取得原有独立门禁所要求的授权。

### 扩展内容与用户价值

用户可以组织个人课程组合，查看跨课程关联而不把不同教材的概念自动合并。
为概念关联保存“来源支持/编辑关联/AI 建议”身份，冲突观点可以并列。
从真实练习记录提出可关闭的复习建议，展示为什么推荐及证据不足之处。
问答引用须支持其结论，证据不足可以拒答，不能把生成流畅度当可信程度。
版本升级先给出受影响的小节、题目与笔记预览，再讨论映射与恢复方案。
规模从课程数量转为个人记录量、教材版本和关联关系的可维护性。

### 验收与升级门槛

- 20 个代表性错误、引用冲突与权限撤销用例均可复现且有明确处理结果。
- 练习建议能回链到真实记录，用户可撤销，不用模型自评声称学习收益。
- 新问答评测逐条检查引用有效性、支持度与拒答质量，开发集与未见评测分开。
- 迁移前后身份数量、未匹配笔记与冲突全部可见，并完成指定版本恢复。
- 课程组合增长时记录响应时间、包大小和恢复成本，依据实测判断是否需要新技术。

### 止步或收缩条件

来源质量、复习价值或版本映射不稳定时，保留静态课程目录与手动复习。
H4a 的 FTS_EVIDENCE_NOT_PROMISING 历史结论保留，新检索方案需新的独立证据。
没有跨课程实际需求时 G3 已是有价值终点，不先建全课程知识图谱。

## 8. G5：有条件的跨库学习协作

### 进入条件

存在具体任务证明外部编排或 Session 汇总能减少用户操作，且 G4 所需记录可靠。
每个消费者明确字段用途、授权范围、撤销方式和依赖故障时的行为。

### 扩展内容与用户价值

Book 提供小型版本化学习语义接口，允许 mygpt 读取被授权的课程/小节/模式摘要。
StudyMate 只交换授权 Session 汇总，Session 不等于知识掌握。
外部工具可以提醒或帮助恢复任务，教材、答案质量与学习记录的权威仍在 Book。
规模只扩到实际需要的消费者；不合并所有数据库，不把 Book 变成通用个人信息平台。

### 验收与升级门槛

- 消费端拒绝未知接口主版本和缺失来源的记录。
- 关闭适配或撤销授权后，基础浏览、四模式与本地记录继续可用。
- 至少一次跨库故障演练验证重复事件、乱序、离线与权限撤销。
- 原始聊天、私人会议、录音和金融账户数据不会随教材接口默认输出。

### 止步或收缩条件

人工导出即可满足需求时保留导出，不为接口数量增加后台服务。
消费者要求超出允许字段或企图取得源数据权威时拒绝扩展。
ChatContextVault 默认无依赖，不引入原始聊天或私人关系资料。
Invest 只引用经济知识材料，教材观点不能直接变成交易信号。

## 10. 触发式复盘与维护

出现新教材、新包格式、重大来源修正、新设备、记录规模瓶颈或跨库消费者时触发复盘。
每次拟升级成长级别时检查：用户价值是否出现、依赖是否满足、证据能否回读、复杂度是否值得。
内容可信度、App 能力与个人数据量分别记录，不用一个“完成百分比”掩盖短板。
只增加功能而未改善真实学习任务时暂停扩展，回到最小可用课程。
恢复演练由包格式、存储方式、版本迁移或环境变化触发；不重复下载身份未变的已核验大文件。
GitHub 保存代码与当前结论，Drive 保存原件和大型成果；同内容再次同步不制造新副本。
冻结证据、旧失败和历史包保留，当前结论可以修订但不能改写来源事实。
预算未明确且无可测增益时，不新增付费 OCR、模型订阅或大规模训练。
Windows 开发侧模型权重与大缓存依全局规则放 D 盘，按真实显存和物理 RAM 规划；Android 使用已授权的应用存储。
