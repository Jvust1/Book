# Book 长期发展路线图

制定日期：2026-09-22。规划视野：未来 12 个月，并保留第二年的方向判断。
性质：发展方案；文中的阶段、数值目标和新接口均为提案，不代表功能已经实现或验收。
执行节奏：全项目组合同时只保留一个主项目和一个支撑项目。本文时间从 Book 获得执行窗口开始计算；阻塞期不以日历强行推进。
当前建议：先把已有教材、App 和恢复入口做成可信的日常学习闭环，再扩课程和智能能力。

## 1. 长期目标与产品边界

Book 成为可长期使用的个人课程系统：同一 App 管多门课程，每节都有预习、学习、复习、刷题四个自由入口。
核心价值是教材可信、学习连续、设备可迁移，而不是增加聊天框数量。
长期成功表现为：用户无需寻找多份旧 ZIP，就能恢复当前教材与学习记录；每个教材结论都能回到原始来源；每个 AI 推导都有明确身份。

- App 通用，教材是独立、版本化的数据。
- 当前产品保持一门课程一本启用主教材；多教材角色先保留合同能力，消费者迁移另做设计审查。
- 教材原文、编辑校注、AI 推导、学习记录、录音与私人会议数据分别存储和授权。
- 四模式不强制顺序，不把停留时间或点击次数当掌握程度。
- 本地优先，Android 与 Windows 复用内容合同；设备差异写清，不假装所有平台功能相同。
- 本路线图不自动批准 H3b、B4b、B5、StudyRecord 版本迁移或新的检索架构。
- 阶段提案获实施授权后仍需满足原有独立门禁；本次只发布规划文档。

## 3. 第一阶段：0–30 天，收拢可恢复基线

### 交付

1. 一份活动分支/PR 依赖表，区分主实现、数据批次、修复和历史快照。
2. 一个可验证的 CURRENT 源码入口与每门教材的独立内容状态表。
3. 经济教材来源问题清单及可接续队列；先原件与身份，再连续录入。
4. Android Studio 可打开的当前工程、构建说明与真实设备验收脚本。
5. 学习记录同步最小回归，包括 UTC、重复导入、冲突、损坏输入和中断恢复。

### 建议验收目标

- 新环境只依靠仓库入口和 manifest，可在 30 分钟内定位、恢复当前候选；大文件下载耗时单独记录。
- 当前每个成果记录准确 source commit、文件大小、SHA-256、Drive ID 与验证范围，身份字段完整率 100%。
- 内容状态按结构审查、定点 PDF 疑点、全页视觉核验、数学独立审查四个维度分别展示。
- 已发现的高风险来源错误不带入正式学习包；未解决的来源项明确可见。
- 同一学习记录包连续导入两次，第二次不产生无意义 revision 更新。
- 原有笔记、教材版本和冻结证据零静默覆盖；回滚用旧版本入口与新恢复分支。

### 前置条件与出门条件

原件无法读取时，只推进已有数据检查与软件稳定工作，不伪造页码或宣布整书完成。
PR 按依赖链分别审阅；本计划不自动合并旧 PR，也不批量删除分支。
没有准确源码身份或原生构建证据时，候选状态保持未验收。

## 4. 第二阶段：31–90 天，完成每日学习闭环

### 交付

1. 选择一门来源可用课程先做完整质量闭环，形成可复制的教材导入模板。
2. 预习展示先备知识与问题；学习展示完整正文和原图；复习展示来源锚点与回忆提示；刷题明确区分原题、提示、参考推导和已核答案。
3. 本地持久化学习记录、最近学习位置、模式独立状态；离线打开已安装课程。
4. Android/Windows 手动同步故障说明和可重复恢复演练。
5. 字号 12–72px 可自由调节，支持小数；实际书宋加载与明确替代分开验收，不附带未经授权的字体文件。

### 建议验收目标

- 一门正式验收课程的正文、题目、图表和来源引用全部闭合，缺失项为零；仍有缺失的版本仅作隔离初稿或局部试用，不计入整书完成。
- 关键学习路径连续使用 14 天，学习记录丢失事件为零；每次异常必须有复现与恢复记录。
- 在目标 Android 真机上完成 30 次启动、退出、重启及断网往返，关键状态一致。
- 390px 级窄屏与常用大字号不发生正文横向裁切；长公式使用可见滚动或合理换行。
- 同一课程在两端抽取至少 20 个来源锚点，题目身份、页码映射和公式内容一致。
- 完整证明和答案的审查覆盖率单独统计，禁止拿自动渲染率代替。

### 前置条件

第一阶段当前身份已稳定；原生构建链可用；选定课程来源可读。
不是所有课程同时追求全量完工。中国经济原件仍缺时，不拖住已可用课程的日常学习验证。

## 5. 第三阶段：第 4–6 月，形成可重复的课程生产线

### 交付

- 固定来源清单、连续页覆盖、原图抽取、结构化正文、QC 队列、独立验收、Course Package 注册七步流程。
- 每条记录保留教材/版本、章节、物理页与印刷页映射、来源区间、结构类型及质量状态。
- 增加新课程只提供数据包与声明，不在 App 里添加课程专属条件分支。
- 以版本化引用保存校注和 AI 推导，使用户能查看原文、修改理由与证据。
- 建立题目/定义/定理/证明/例题的完整性检查，跨页连接与公式歧义进入定点 PDF 队列。
- 为真实学习使用建立匿名本地错误反馈入口，不采集无关屏幕或私人消息。

### 建议验收目标

- 连续两门课程通过相同导入工具和质量门，App 业务代码因课程差异的修改为零。
- 可重新执行的数据生成步骤保持确定性；相同输入、工具版本与配置产生相同业务内容哈希。
- 任一校注能够定位原始版本并关闭误报，不破坏原文历史。
- 100% 的高风险开放项均有责任任务、来源锚点和下一核验动作。
- 每月一次抽样恢复，清单与实际字节匹配率 100%；不反复下载已经验证且身份未变的大文件。

### 技术取舍

先保留现有 Python Runtime、SQLite 与前端合同。只有实际维护/性能瓶颈有测量证据，才引入新数据库或服务。
检索改进先在新且未污染的评测集上做影子比较；H4a 的 FTS_EVIDENCE_NOT_PROMISING 历史结论不可改写。
课程生产线成熟前，不先做大规模自动知识图谱或全课程智能体。

## 6. 第四阶段：第 7–12 月，受控学习智能与跨设备体验

### 交付候选

1. 基于真实练习记录的复习建议，显示依据和不确定性，并允许用户关闭。
2. 教材证据问答的来源充分性评测，拒答/引用验证继续独立于模型生成。
3. 课程版本升级与学习记录迁移的预览、冲突处理、恢复方案；需单独迁移门批准。
4. mygpt 只读学习语义事件接口，StudyMate 只交换经授权的 Session 汇总。
5. 在手动同步稳定后，评估可选增量同步；默认不把录音与私人会议资料混入教材同步。

### 建议验收目标

- 新问答评测逐条检查引用有效性与答复支持度，不能只测答案是否流畅。
- 20 个代表性错误、冲突、权限撤销用例全部有可复现证据。
- 推荐功能用用户实际接受/撤销及学习负担评估；不用模型自评代表学习收益。
- 跨库适配关闭后，Book 本体浏览、四模式和记录继续可用。
- 任何迁移都先跑只读预览，校验前后身份数量并完成一次恢复演练。

第四阶段是条件性目标；前面内容质量与记录稳定不达标，就延后智能功能。

## 8. 首个两周执行包

- 第 1–2 天：完成 BK-01，保留现有 PR 身份，指定下一唯一执行分支。
- 第 3–4 天：重排数学内容与经济来源队列；明确哪一本可进入完整验收。
- 第 5–7 天：先关闭记录丢失、同步错误、阅读阻断等 P0；来源受阻则不猜补。
- 第 8–10 天：真机完成阅读/字号/模式切换/重启和手动同步；失败转为可复现用例。
- 第 11–14 天：冻结一个可用候选，独立复核、生成恢复 manifest，开始真实学习试用。
- 唯一首步：核对 BK-01 的当前入口与 PR 依赖；不先大改 UI 或数据库。

## 9. 跨库关系

| 项目 | Book 提供/接收 | 边界 |
|---|---|---|
| mygpt | 提供课程/小节/模式/进度摘要 | 教材与学习记录权威仍在 Book |
| StudyMate | 可接收用户允许的 Session 汇总 | Session 不等于掌握程度 |
| AutoFlow | 可辅助受控的整理任务 | 自动点击不能代替内容验收或合并授权 |
| Invest | 仅作为经济知识学习材料来源 | 教材观点不直接变为交易信号 |
| ChatContextVault | 默认无数据依赖 | 不引入原始聊天和私人关系资料 |

接口尽量使用小型、版本化、可导出的 JSON 合同；不急于合并仓库或统一全部数据库。

## 10. 指标、预算与停止条件

| 指标 | 当前基线 | 建议目标/解释 |
|---|---|---|
| 全书独立数学验收 | r6 尚未完成 | 按教材逐项证明，不用测试数代替 |
| 经济内容来源疑点 | 货币金融学 501 项 | 优先关闭高风险；总数可能随发现增加 |
| 丢失学习记录 | 本轮无新真机测量 | 候选试用期 0 次 |
| 恢复可用性 | 已有归档校验 | 30 分钟定位/恢复目标，单列下载时间 |
| 交付可追溯率 | 各 PR 证据分散 | 当前候选 100% 身份字段完整 |
| 使用价值 | 未采集长期数据 | 先 14 天实际使用再扩功能 |

默认利用已有 Windows 设备与 Android 手机；本地模型/大缓存放 D 盘，按真实显存与 RAM 规划。
没有明确增益与预算前，不增加付费 OCR、模型订阅或大规模 GPU 训练。
发现来源身份不明、Golden 内容意外变化、记录丢失或数学高风险错误时，暂停相关发布，保留可用旧包。
连续两个周期只有功能增加、没有可用性证据提升时，停止扩展，回到一门课程的真实使用闭环。

## 11. 每月复盘与维护

每月检查四件事：实际学习是否更顺畅、来源疑点是否下降、恢复是否可靠、复杂度是否增加过快。
将任务标为未开始/进行中/待验收/完成/阻塞；完成必须链接具体 commit、测试或人工内容审查证据。
新事实修改当前结论，旧失败与冻结结果保留；不为追求路线一致而掩盖已发现问题。
重大设计先对标再实现；一个阶段完成后重新比较成熟方案，允许更换路线。
每次接续先读取本路线图与当前治理文件；如已有更新的用户任务，调整优先级并记录原因。
